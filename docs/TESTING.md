# Testing notes

Maintainer-facing content that used to live in the README: what every installer
must contain (checked per release), and the manual test checklist covering the
OS-specific paths that cannot be exercised during development on Linux.

## 🧪 What ships in every installer (checked per release)

| Piece                               | Where it comes from                                                                                                                                                                                                                                                     | What breaks without it                                                              |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `yt-dlp` engine                     | official [yt-dlp releases](https://github.com/yt-dlp/yt-dlp/releases)                                                                                                                                                                                                   | no downloads at all                                                                 |
| `ffmpeg` (`ffmpeg.exe` on Windows)  | static builds pinned + checksum-verified by CI: [BtbN LGPL build](https://github.com/BtbN/FFmpeg-Builds) (Linux) · [ffmpeg.martin-riedl.de](https://ffmpeg.martin-riedl.de) static build (macOS) · [gyan.dev essentials](https://www.gyan.dev/ffmpeg/builds/) (Windows) | stream merging + audio extraction degraded to single-format downloads               |
| `deno` JS runtime (`deno.exe`)      | official [Deno releases](https://github.com/denoland/deno/releases)                                                                                                                                                                                                     | YouTube's anti-bot wall cannot be evaluated (Node fallback: x.com posts still work) |
| update feeds (`latest*.yml`)        | generated by CI                                                                                                                                                                                                                                                         | app self-update disabled                                                            |
| `third-party/` (notices + licenses) | repo `THIRD_PARTY_NOTICES.md` + `LICENSES/` via `extraResources`                                                                                                                                                                                                        | redistributions lack the required license texts / source offers                     |

Settings → **Engine** shows the live versions of all three.

## 🧪 Manual test checklist (Windows / macOS — things that cannot be exercised on Linux)

After installing, these should take ~5 minutes and cover the OS-specific paths:

1. **Launch** — Windows: SmartScreen prompt → _More info → Run anyway_; macOS:
   mount the dmg, drag to Applications, right-click → Open (skip Gatekeeper).
2. **Settings → Engine** — yt-dlp, ffmpeg (**`ffmpeg.exe` on Windows**), and
   the JavaScript runtime rows all show versions (not "not found").
3. **Titlebar** — frameless window minimizes / maximizes / closes.
4. **YouTube preview** — paste a video URL, check thumbnail + duration card.
5. **Download a short video** at 720p — the queue fills, the row completes,
   History shows it; **Show in folder** and **Open** both work.
6. **Audio extraction** — `Audio only · MP3` completes (proves the bundled
   `ffmpeg.exe`/`ffmpeg` is executable — packaging path fixed in 0.2.7, see
   [CHANGELOG](../CHANGELOG.md)).
7. **Engine update check** — Settings → Check engine updates responds, and the
   app update check in the titlebar opens the dialog (macOS: it must offer
   _Open releases page_, never _Update_ — in-place updates are disabled on
   unsigned builds).
8. **macOS only** — cookie store read from **Safari**: pick "From a browser" →
   Safari and preview an Instagram post. If that reports `Operation not
permitted` / "failed to load cookies", grant Meowdler Full Disk Access
   (System Settings → Privacy & Security → Full Disk Access) and retry.
9. **Windows only** — after a config-folder change in NSIS, downloads still
   land in the chosen output folder.
10. **Engine swap guard** (any OS) — with a short download running, pick
    Settings → Engine → _Install engine update_ right after a check reports a
    newer engine: the item must stay queued and the app must answer with the
    "engine is in use" note, never swap mid-download. While nothing runs, the
    same button completes and Settings → Engine shows the newer yt-dlp.
